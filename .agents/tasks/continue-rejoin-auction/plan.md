## 2. Design decisions (these go into the final report)

1. **Status mapping (server-derived, `room-summary.ts`)**. `ongoingStatus`:
   - `CLOSED` -> `CANCELLED`, `COMPLETED` -> `COMPLETED`. Both are never returned by the ongoing list.
   - `PAUSED` -> `PAUSED`; `STARTING|RUNNING` -> `LIVE_AUCTION` (a round that is exhausted but not ended stays `LIVE_AUCTION`).
   - `LOBBY` with retention phase `TEAM_SELECTING` or `ALL_TEAMS_COMPLETED` -> `RETENTION_IN_PROGRESS`.
   - `LOBBY` startable (retention `OFF` or `FINALIZED`, and `teams.length >= settings.minimumParticipants`) -> `READY_TO_START`.
   - `LOBBY`, `teams.length < minimumParticipants`: `teams.length === 1` -> `NOT_STARTED`, otherwise `WAITING_FOR_TEAMS`.
   - `LOBBY`, enough teams, retention enabled but phase `NOT_STARTED` -> `NOT_STARTED`.
   The summary also carries `resumePath` (server-chosen: `/room/CODE/retention`, `/room/CODE`, `/auction/CODE`, `/results/CODE`) so the client holds no routing rules.
2. **Last activity**: new optional `Room.lastActivityAt`, set in `RoomManager.mutate` (when events exist) and `create`; falls back to `createdAt`. It is inside the snapshot, so it persists atomically with the change; no migration.
3. **Players sold/remaining**: `playersSold` = purchases whose `acquisitionType !== 'RETENTION'`; `playersRetained` separate; `playersRemaining` = WAITING players + active player + queued recall players (null before the pool exists, i.e. LOBBY with empty `players`). Round = active player's `round`; category = active player's `potId`.
4. **Timer across a server restart**: the wall-clock deadline `endsAt` is authoritative and keeps running while the server is down. On boot `recover()` + `timers.schedule` resolve an overdue lot exactly once (sold to the highest bidder, else unsold) using the existing `activationId` guard, and an overdue `nextPlayerAt` activates the next player. PAUSED rooms keep `remainingTimeMs` and are never scheduled; resume sets `endsAt = now + remainingTimeMs`. No grace extension and no implicit pause are added (an implicit pause would violate "paused only by host"). Document this and the residual risk (a long outage can resolve a lot with nobody able to bid). Tests pin the behaviour.
5. **Duplicate connections**: a user may hold several sockets (tabs/devices); all receive events; presence counts the user once; commands stay idempotent through `requestId` receipts and `expectedSequence`. Hard cap of 8 sockets per user: the oldest is closed with code `4003 Superseded` after an `ERROR` event, and the frontend treats 4003 as terminal (shows "Reconnect to Auction" instead of fighting).
6. **WebSocket auth**: browser sends `Sec-WebSocket-Protocol: auction.v1, bearer.<jwt>`; `buildApp` registers `@fastify/websocket` with `handleProtocols` that selects only `auction.v1` (the token is never echoed). `preValidation` reads the bearer from that header after `Authorization`. The `?token=` query remains accepted for non-browser clients, marked deprecated in `WEBSOCKET_PROTOCOL.md`; the logger already drops the query string, a test asserts no log line contains the token. Frontend stops putting the token in the URL.
7. **Presence**: `PresenceTracker` (in `realtime/presence.ts`) keeps live per-user socket counts and `lastSeenAt`; `lastSeenAt` is written (best effort, never blocks) to new table `live_room_presence` on first connect and on last disconnect, and loaded lazily per room so "last seen" survives restarts. Table missing or failing never breaks the hub (memory fallback + one warning). `ROOM_STATE.teamPresence` (team id, `connected`, `lastSeenAt`, manager username) is sent **only to the host**; others keep `connectedUsers`. `PRESENCE_UPDATED` is sent per-connection (host variant carries `teamPresence`). Disconnected teams are never removed.
8. **Host policy**: no host transfer and no auto-pause on host disconnect exist today; keep it that way and document it.
9. **Rejoin by code**: `POST /api/rooms/:code/rejoin` is read-only and idempotent; it only succeeds for an existing member (team derived from `request.auth.userId`), never accepts a team name/id, returns the summary and `resumePath`. Non-member -> 403 `NOT_ROOM_MEMBER` with a message that says to use "Join Auction Room"; unknown -> 404; CLOSED -> 409 `ROOM_CLOSED` ("This auction was cancelled."); COMPLETED -> 200 with `canContinue=false`, `resumePath=/results/CODE` (view only).
10. **History/activity restore**: `ROOM_STATE` gains `activity` (last 60 entries derived server-side from `bids`, auction `purchases`, `playerHistory`, `retention.turns`, stable ids, newest first) and `recentBids` (last 20 bids of the active player). The frontend feed is rebuilt from the snapshot on every `ROOM_STATE` (the hub always sends one after events), so refresh keeps the feed and no duplicates are possible.
11. **Sequence/duplicate-event protection in the client**: events with `sequence > 0` and `sequence <= snapshot.sequence` (except `PRESENCE_UPDATED`, `ROOM_STATE`, socket-local sequence-0 events) are dropped; `ROOM_STATE` older than the held one is dropped.
12. **Reconnect policy (client)**: delay = `random(0, min(30000, 1000 * 2^attempt))` with a 500 ms floor (full jitter); after 8 failed attempts status becomes `LOST` and a "Reconnect to Auction" button appears (manual attempt resets the counter); `online`, `pageshow` and `visibilitychange(visible)` trigger an immediate attempt; app-level `PING` every 20 s while `SYNCED` and a forced reconnect when no frame arrives for 55 s; close code 4001 or a missing session -> `AUTH_EXPIRED` with "Your session expired. Sign in again to rejoin your auction." The "Connection lost..." text appears only after 3 s of not being `SYNCED`; "You're back! Reconnected to your team." shows for 4 s after recovery. No modal popups.
